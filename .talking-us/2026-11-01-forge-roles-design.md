# U03 可配置功能角色与全局绑定

范围：[本轮需求 U03](20261031-233358-账号权限三方API与群通知-详细需求文档.md)，FR-GV-01/13/17/20。此增量是 U03 的全局角色闭环；组织范围绑定、用户组与数据策略和组织树一起实现，仍保留在 U03/U04 未完成范围中，不接受尚不能执行的组织/组授权配置。既有账号数据范围不变。

## 行为与入口

- 「账号与权限」下的账号、功能权限为真实页签；有任一页签读取权限即可进入，进入时只请求获准页签。继承现有 legacy 控制台布局与表单、确认框、分页、错误和 pending 状态。
- 功能权限按域分组展示当前实现的权限码。角色列表、详情、创建、编辑名称/说明/权限/状态、复制、删除、恢复内置模板、有效权限预览；预览不切换身份。角色代码创建后不可变，格式 `[a-z][a-z0-9_]{0,31}`；名称 1–128、说明 0–1024；拒绝控制字符、空白名称、重复代码、未知权限、普通角色的 `*`。
- 平台管理员固定激活、固定全部权限，不可编辑、停用、删除；其身份仅能由有效平台管理员通过账号主角色授予。其它内置角色可修改/停用/恢复模板，不可删除；自定义角色删除受有效账号（包括停用账号）、服务账号、附加绑定、SSO 映射、数据策略引用保护。删除保留角色历史及代码，不复用代码。
- 用户保留一个主角色（兼容 users.role），允许主角色为自定义角色；附加角色通过角色绑定持久化。有效功能权限为全部激活角色的并集；停用角色仍显示已有绑定但不贡献权限。角色恢复后授权恢复。角色编辑下一次 HTTP/SSE 检查生效，不修改账号资料/数据范围/SSO 绑定。删除账号后的绑定不会赋予重用登录名的新 ID。
- 账号表单使用服务端可授予角色目录、主角色和附加角色选择；只改资料不清除现有停用角色绑定。新增绑定须为激活角色，附加角色不能含 platform_admin、重复或等于主角色；最多 32 个附加角色。账号详情显示有效权限。账号绑定变化使用账号 revision，同事务审计。
- 服务账号同样支持主角色与附加角色并集，禁止任何 platform_admin 绑定。保留现有 org/all 数据范围。服务账号写入重读操作者并校验授权上限；成功审计同事务。调度触发读取当前有效权限，没有 agent.run 时暂停，不借创建者权限运行。旧服务身份调度继续使用原 subject，但功能权限上限取当前有效创建账号与 user 模板交集。

## 授权与竞争

API 读取需要 role.view，写需要 role.manage，角色是平台级配置，写还须现有数据范围 all。编辑或复制已有角色、管理目标账号时，操作者必须覆盖目标**全部已配置**权限（包含停用角色），新值也不能超额；防止先停用高权角色再由低权限者接管。非平台管理员不能管理 platform_admin/org_admin 身份；不能用复制通配符获得平台管理员。复制平台模板展开为当前具体权限码，仅真正具备全部这些权限的操作者可复制。

所有角色、绑定、SSO 映射及账号写入共用现有 identity.account-lock，再读操作者、目标和角色授权并 CAS。角色和绑定的校验、变更、成功审计一个事务；未知/停用角色不能被新授予；冲突不修改任何授权。角色编辑与账号授予串行，避免“低权校验后高权写入”。现有角色不被 seed 覆盖。角色表缺失/读取失败不回退静态默认授权。

## 数据与查询

012_roles 新增 roles（id/key/name/description/builtin/status/revision/created/updated）、permissions（key/domain/kind/description）、role_permissions（复合主键）、role_bindings（id/role/principal_type/principal_id/scope_type/scope_id/created_at）。scope_type 本增量只允许 global，scope_id 用非 NULL 空字符串避免 MySQL UNIQUE 的 NULL 绕过；唯一键覆盖角色/主体/作用域。新增角色、绑定 ID 前缀 rol/rbd，沿用 CHAR(26) ascii_bin。Role key 与已有 users.role/service_accounts.role 长度一致。

迁移初始化现有六角色及现有权限模板；目录只登记实际受支持动作。重复执行恢复缺失 DDL、校验列/索引/外键；角色初始化只在首次插入时填默认权限，绝不重置空权限或已编辑矩阵。唯一迁移器沿用命名锁与 schema_migrations，Drizzle 仅生成增量，fresh schema 与升级一致。

用户/服务账号查询用 SQL 相关子查询返回 authorization_json：roles 元数据、激活角色去重权限、所有配置角色去重权限。主角色与 global 附加绑定取并集；permissions 主键自然去重，不使用可能截断的 GROUP_CONCAT，不在用户列表逐行发额外查询。真实数据库行始终转换为显式 permissions 数组，缺失/畸形快照默认拒绝；手工构造的可信测试/内部 Principal 可继续使用模板帮助函数，真实登录/锁内授权/调度不走该回退。平台通配符仅主角色 platform_admin 且对应角色激活时产生。

机制实验：本机真实 MySQL 隔离临时库 `/private/tmp/forge-rbac-sql-probe.mjs` 验证相关 JSON 聚合、去重、停用排除、配置授权上限保留、FOR UPDATE 兼容，结果 PASS（`/private/tmp/forge-rbac-sql-probe.txt`）。机制实验不等于 API/页面验收。

## 接口、身份及错误

- GET /admin/api/permissions：兼容 roles 映射，新增 catalog；权限值来自数据库。
- GET/POST /admin/api/roles；GET/PATCH/DELETE /roles/:id；POST /roles/:id/copy、/reset；详情返回代码、状态、权限、内置标志、revision、can_manage 与引用数量；创建返回 id/revision，修改/删除/恢复要求 If-Match。复制要求源版本 If-Match，源变更返回 409。
- 用户及服务账号请求新增 additionalRoleIds，返回 roles、additional_role_ids/effective_permissions；用户列表保留 grantableRoles 兼容，新增 roleOptions（包含 key/id/name/status）；不要求 user.manage 用户另具 role.view 才能管理已获准账号。
- SSO 映射允许激活自定义主角色。维持现有“多个映射选主角色”的兼容顺序：内置优先 platform_admin/org_admin/builder/operator/auditor/user，自定义按 key 字典序；本次不自动把外部每个角色新增为本地绑定。已有绑定账号始终保留本地角色，仅用有效显式映射判断 SSO 渠道准入；新建用户从选中角色初始化 self。映射写入同锁重读操作者，不能经 sso.manage 映射更高权限。seed 仅首次初始化映射，不覆盖后台维护结果。
- 沿用错误体系：401 会话失效、403 权限/授权上限、404 未知角色/不可见账号、400 格式/未知权限/新增停用绑定、409 引用/重复/版本冲突、428 缺版本；日志没有密码/Token。角色日志归属平台，账号授权日志归属账号组织，拒绝日志按可信操作者组织。

# Forge Job 与消息管理接口设计

版本：1.0　日期：2026-11-01　状态：**READY FOR IMPLEMENTATION（设计契约，尚未实现）**

依据：[需求](20261101-113405-Forge后台优化与Job消息管理-详细需求文档.md)、[开发设计](20261101-113405-Forge后台优化与Job消息管理-开发设计文档.md)、[数据库](20261101-113405-Forge后台优化与Job消息管理-数据库设计文档.md)。新接口、Scope、错误码和DTO均是待实施规格；本轮不修改contracts源代码、不生成冒充已部署的OpenAPI。实现时所有Schema统一进入packages/contracts，生成OpenAPI 3.1/SDK与契约测试，以下名称为唯一字段来源。

## 1. 通用合同

- 管理端 `/admin/api`：现有Cookie/CSRF，实时功能权限＋数据策略；开放端 `/open/v1`：App Key有效Scope交集＋Job显式授权＋本App归属；集成端 `/integration/v1`：现有Principal验签＋本地权限/外部范围交集。Connector不访问任何admin或消息配置接口。
- 不可见资源统一404。仅具动作权限但缺功能权限403。所有写入先认证/功能权限→可见性/可写范围→Schema→当前身份/引用→幂等→版本/状态检查→事务。重放幂等结果前仍检查当前授权，撤权后不能读旧响应。
- 配置和人工/执行控制的PUT/PATCH/DELETE/动作POST使用强If-Match，值为所读资源的十进制revision双引号；缺失428 CFG-8505、格式400、版本冲突409。创建无If-Match；控制读执行stateRevision，消息重发读delivery.stateRevision，不能拿Job的revision代替。
- 创建执行、控制、人工决定、测试/重发需 `Idempotency-Key`（1–200 ASCII可见字符，去首尾空白，不允许控制字符）。scope为服务端操作＋主体＋资源的SHA256，存既有64位scope列；同键同规范请求重放原响应，同键异体409。重放优先于旧If-Match，状态变化不使已成功命令被重复执行。
- JSON拒绝未知字段；`null`仅用于明确可清空字段，不等于省略；数值不接受字符串/NaN/负数。金额固定6位十进制**字符串**，日期RFC3339 UTC，ID接受既有ID_PATTERN但新生成完整ULID。新资源长度、JSON UTF-8总量、批次与运行限额统一引用需求L01–L09。
- 新Job/Eval受理JSON路由bodyLimit=1MiB（请求体实际UTF-8字节），越界413 CFG-8506；单项64KiB按其规范序列化校验。此规则不修改既有Run/文件上传路由的bodyLimit/错误兼容合同。
- 列表：`limit=50`，1–200；`cursor`为不可编辑的不透明游标，绑定筛选hash、lastCreatedAt及lastId；排序createdAt DESC,id DESC；响应`{items,nextCursor}`。时间过滤`createdFrom`含、`createdBefore`不含，必须带时区，非法区间400。列表SQL带同一AccessContext，不先取全量再筛。
- 成功查询200、创建201、异步受理202、引用安全删除204；异步响应不等于完成。错误统一`{error:{code,message,requestId,details,remedy}}`；字段错误`details.fields:[{path,issue}]`，批次路径包含项索引，无秘密回显。

## 2. DTO、枚举与边界

### 2.1 Job配置和受理

| DTO | 完整字段合同 |
| --- | --- |
| JobWrite | `key`仅创建必填；创建时`name,businessType,draft`必填，description默认空；`orgUnitId`可省略取调用者组织，跨组织/平台须授权；`responsibleUserId`可空；`status`仅active/disabled，创建默认disabled，启用须有可运行发布版。PATCH各字段可省略保留，key/组织/businessType发布后不可改，deleted仅DELETE产生 |
| Manifest | `schemaVersion:1`；`target:{kind,key,version,checksum}`必填；kind=agent/flow/skill/external/evaluation，全部来自注册目录；`inputSchema/outputSchema`必填；`nodes`为流程时必填、其余空数组；flow必填`outcomeNodeKey`（循环外每业务项唯一聚合节点）；`limits:{maxConcurrentExecutions,maxParallelItems,stepTimeoutSeconds,activeTimeoutSeconds,waitTimeoutSeconds,maxAttempts,maxCostUsd}`按L03–05填缺省；`resourcePolicy/eligibilityAdapter`为已登记引用，不接受任意锁值/URL |
| Node | `key,kind,dependsOn,inputMapping,outputSchema`必填；kind=agent/domain/script/browser/external/human/gate/condition/map/join；`target`按kind条件必填；`condition`为受限JSON表达式或null；`maxIterations`默认1、1–100；`timeoutSeconds,maxAttempts`按L04/05；依赖存在/汇合和有界回环由发布验证 |
| JobInvoke | `input`必填JSON对象；`businessRef`必填`{type:string,id:string,period?:string}`，ID1–128码点、type1–64；`items?:[{key:string,input:object}]`，无批次时省略；`versionId?`仅获准管理调用可传，否则选当前发布版；API/集成不得自报actor/appId/orgUnitId、businessKeyHash、fence或secret |
| ExecutionAccepted | `executionId,jobId,jobVersionId,generation,status,stateRevision,createdAt,statusUrl`；202时status可queued/waiting；幂等重放返回相同ID，不承诺仍是原状态，调用者随后GET最新状态 |
| JobDetail | `id,key,name,description,businessType,orgUnitId,responsibleUserId,status,revision,publishedVersionId,draft,createdAt,updatedAt`；无Job编辑权时不含draft；GET带ETag |
| AppGrantWrite | `appId,actions,status`必填；actions非空去重数组，仅run/read/cancel，且必须在操作者和应用当前Scope上限内；status=active/disabled；受Job父ETag保护，不能自授权其它App |

Manifest注册目录的input/output Schema均为受限JSON Schema 2020-12；不允许远程`$ref`、未登记代码或无法限制的循环。发布后版本不可变。Skill/浏览器目标同时受既有执行环境资格，不把JSON声明当授权。

条件与映射使用以下固定语法，不执行表达式字符串或动态JS：

- 引用为`{ref:"/input/projectId"}`，使用绝对JSON Pointer（仅~0/~1转义），根只允许input/businessRef/item/steps；steps是本业务项当前可用、已完成的依赖输出。只读自有属性，拒绝__proto__/prototype/constructor、通配符、函数和跨执行引用。缺失值是missing，不自动变null或0。
- inputMapping由`{literal:JSON}`、`{ref:pointer}`、`{object:{字段:映射}}`、`{array:[映射]}`四类组成且恰好一种；最大深度8，解析结果必须符合目标inputSchema。引用缺失失败QAL-7301，不能默默补默认业务值。
- condition为布尔常量，或`{op:"exists",ref:pointer}`、`{op:"eq|ne|gt|gte|lt|lte|in",left:取值映射,right:取值映射}`、`{op:"and|or",args:[condition]}`、`{op:"not",arg:condition}`。复合深度≤8，args为1–20项，整表达式≤16KiB规范JSON；eq/ne为类型严格的规范JSON比较，大小比较仅有限JSON数值，in右侧必须数组；任一取值missing除exists外均false，类型不合法发布/运行校验失败。
- Node.key沿Key规则且同manifest唯一，dependsOn只指已定义节点；只允许声明了maxIterations的回边，outcomeNodeKey不在回环中。编译检查引用的依赖先于使用可用，跨轮只读取已提交上一轮结果，不用正在运行或其它明细的临时输出；超过L02展开上限失败JOB-7110。

例如`{op:"exists",ref:"/steps/metrics/output/value"}`只检查本项指标输出是否存在，不调用外部服务；是否达到分类阈值等业务条件仍由受信业务适配器配置/校验，模型不能改写该条件。

### 2.2 执行、控制与结果

| DTO | 完整字段合同 |
| --- | --- |
| ExecutionSummary | `id,jobId,jobVersionId,businessRef,triggerType,triggerRef,subject:{type,id},status,waitReason,generation,stateRevision,counts:{total:null或整数,succeeded,failed,unknown,skipped},activeMs,costUsd,reservedCostUsd,costLimitUsd,qualityStatus,deliveryStatus,startedAt,completedAt,createdAt`；全部日期允许尚未发生时null |
| ExecutionDetail | Summary＋`stepsUrl,eventsUrl,artifactsUrl,messagesUrl,error:{code,message,remedy}或null,inputSnapshot,output,allowedActions`；正文被清理时inputSnapshot/output为null并带`payloadPurgedAt`，绝不伪造空结果；allowedActions由当前权限/状态生成但服务端仍独立检查 |
| StepDetail | `id,key,itemKey,iteration,kind,status,generation,stateRevision,attemptCount,successfulAttemptId,sideEffectState,inputHash,resultRef,error,waitReason`；正文引用要单独鉴权；attemptCount全程单增 |
| AttemptDetail | `id,stepId,attemptNo,generation,status,sideEffectState,runId,codeExecutionId,externalOperationId,submittedAt,confirmedAt,completedAt,error,resultRef,isStale`；不返回票据/fence所有权凭证、原始敏感载荷 |
| ExecutionControl | `action`必填pause/resume/cancel/retry_failed/rerun；`reason`必填L01；`stepIds?`仅retry_failed可选1–100个该执行可见失败步骤；省略取全部可重试失败项，服务端按L02展开上限分批枚举，不能把1000个业务项误当1000个技术步骤；`acknowledgeSideEffects`遇副作用的rerun必填true。不能用resume跳过对账 |

| HumanDecision | `action`取该任务允许动作；`reason`必填；`patch?`按任务输出Schema；`evidenceIds`为已存在且有权证据ID数组0–100项；放行/确认外部结果至少1条证据，或结构化人工核实记录；`expectedInputHash`必填。操作人来自会话，客户端不能传decidedBy |
| DeliveryObservation | `status`仅pending/delivered/blocked/waived；`reason,evidenceIds,businessVersion`必填；证据由适配器回读或获准人工录入。不是普通Job取消/Run成功自动推导；使用独立deliveryRevision条件写入 |

Job status：`queued/running/waiting/pausing/paused/cancelling/succeeded/partial/failed/cancelled/skipped`。waitReason：`approval/human/external/reconcile/resource/budget/previous_execution`或null。step status：`blocked/ready/dispatched/running/waiting/succeeded/failed/cancelled/skipped`。attempt status：`prepared/submitted/running/succeeded/failed/unknown/cancelled`。sideEffectState：`not_submitted/submitted/confirmed/unknown`。审批继续使用已有Run/approval DTO，不复用HumanDecision假扮审批。

DatasetWrite：创建`key,name,source:{kind,reference,permissionRef}`必填，description默认空，orgUnitId默认当前组织；`status?:active/disabled`默认disabled，启用须合法来源及1–1000条用例，PATCH省略保留；kind=repository_fixture/provided/authorized_derived；CasesWrite：`cases:[{seq,input,expected,scoring}]`，seq唯一、1–1000，评分引用受信规则；EvalInvoke：`datasetId,datasetRevision,agentVersionId,comparisonAgentVersionId?,costLimitUsd`，预算显式且≤调用者上限，数据集active且版本匹配，LLM未授权不执行；Review：`score(0–1),reason,evidenceIds`＋结果ETag。真实/合成样本不伪装生产来源。

文件上传/下载/解析、workspace与code execution继续使用[既有E3接口](2026-10-31-forge-interface-design.md#3-文件skillworkspace与执行环境接口)。增加Job关联时服务端验证executionId/stepId/业务版本与上传者范围；非LLM产物不要求伪造Run。下载短期签名URL只在ready且授权后发放，路径/对象key不作API输入。

## 5. 受信适配器结果回收

`POST /internal/v1/job-step-attempts/{id}/result`只用于受信执行适配器，不属于管理或Connector稳定公开接口。使用服务身份＋HMAC校验 method/path/timestamp/bodyHash，时间偏差≤300秒，密钥由凭据库管理。身份固定允许的adapterKey，不接受body自报权限。

请求：`adapterKey,externalOperationId,resultMessageId,status,sideEffectState,requestHash,resultHash,output?,evidenceFileIds,observedAt`，requestHash必须匹配已持久派发；status仅succeeded/failed/unknown/cancelled；output经过目标Schema和文件权限校验。重复同resultMessageId/hash返回200原接收结果，异hash409；旧generation结果保存为过期证据并200 `{accepted:true,stale:true}`，绝不推进当前步骤。未提交attempt或不匹配adapter/operation为403/409，无业务回写。

只有匹配attempt并经过回读/质量检查才推进Job；外部的success文本不能直接写整个执行成功。查询回收走同一结果入口。持久化失败返回503，调用者按同ID重试，不重新执行外部动作。

## 6. 事件、Webhook与兼容

- Job SSE按job_events.seq严格递增，`id=seq`，`Last-Event-ID`精确续传；事件清理后返回reset与当前执行快照。心跳与身份重验沿用现有streamRun机制，不承诺逐token流。
- Job事件：`job.queued/started/waiting/paused/resumed/completed/partial/failed/cancelled/skipped`、`job.step.updated`、`human.required/resolved`、`quality.checked`、`delivery.updated`；每条含`eventId,type,version:"1",createdAt,executionId,generation,seq,data`，seq为十进制字符串以保留BIGINT精度。事务提交前不能发送；data为脱敏摘要与引用。
- 面向人的消息默认订阅Job完成/失败/待人工与嵌套审批所映射的Job待审批事件；非Job直接Run继续按已确认三事件配置通知。Job开始/积压/交付逾期等为显式启用规则。步骤事件默认不群发。
- 通用新Webhook envelope为`{id,type,version,createdAt,data}`；data含executionId/generation/status/statusUrl及获准摘要，无内部票据/对象路径。固定JSON序列化结果入队后不变。
- **旧App回调**保持已有`id/type/version/createdAt/appId/data`结构、run.completed等原事件、usage/resultUrl及`evt_{runId}`事件ID。保留deliveryId和逻辑payload；待发/重试按原serializer生成冻结body并核对签名向量，历史无原始字节时不伪造。不能将新Job envelope发给旧接收方；旧规则仅匹配原直接App Run，不自动扩到新Job嵌套Run。
- 发送Headers沿用`X-Forge-Event-Id/Event-Type/Delivery-Id/Timestamp/Signature`；HMAC-SHA256对`${timestamp}.${body}`，Signature=`t=...,v1=...`。重试eventId、deliveryId和body不变，timestamp/签名按本次有效Secret生成；接收方按eventId幂等，不能承诺网络上恰好一次。
- 原管理应用请求字段webhookUrl/webhookSecret/webhookSecretId转调同一渠道服务；任意channel配置修改在同事务递增关联App revision并更新message_channel_revision，因此旧App If-Match覆盖其读过的渠道基准。兼容App响应增加webhookChannelId/webhookChannelRevision/webhookConfigured，旧URL仅掩码；新旧页面不能把掩码回写。直接channel写与App写均App→channel锁序，公开事件/签名不变。
- 原`/admin/api/apps/{id}/webhook-deliveries`与`/admin/api/webhook-deliveries/{id}/replay`兼容映射M05/M06，仅在原App等价范围内授权，追加attempt不清零历史；不授予message全域管理。旧schedule管理入口映射J11，只允许其Agent型兼容Job；其它类型需新入口，不能使旧agentId字段指向非Agent对象。

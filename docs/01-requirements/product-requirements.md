# Forge 产品需求文档（V2）

版本：2.0　日期：2026-10-21　状态：待评审

## 1. 背景与目标

Forge 是公司自用的通用 Agent 后端开发框架。每个客户项目私有化部署一套，通过安装能力包和编写配置交付，而不是复制一套代码二次开发。

### 1.1 业务目标

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | 新项目以配置为主交付 | 标准 Agent 项目 1–2 周上线；框架代码零修改 |
| G2 | 能力可插拔 | Agent / Skill / MCP / 工具包 / 模型供应商均可在控制台安装、升级、回滚、卸载 |
| G3 | 对外开放 | 业务系统通过统一开放 API 调用已发布 Agent，具备鉴权、配额、Webhook、文档 |
| G4 | 企业治理 | 功能权限 + 数据权限、审批、预算、凭据、审计、数据保留可配置 |
| G5 | AI 可维护 | 需求、接口、数据、目录文档与 `AGENTS.md` 同仓；契约变更可检查 |
| G6 | 统一身份与交付 | 公司所有项目接入统一 SSO；Forge 发布遵循线上发布规范，SSO/Connector 按环境灰度 |

### 1.2 产品原则

1. **MySQL 是唯一系统数据库**：不提供 SQLite/PostgreSQL 运行模式；开发、测试、生产统一 MySQL 8.0.30+。
2. **配置优先，代码兜底**：Agent、Skill、MCP、OpenAPI 工具、模型端点优先声明式配置；只有非标准协议才写代码。
3. **平台能力可插拔，运行版本可追溯**：任何安装/升级/回滚都有记录；运行固定在某个版本与策略快照上。
4. **默认安全**：最小权限、凭据不进入提示词与工作流历史、高危操作审批、外部输入不信任。
5. **私有化优先**：离线可安装、可备份恢复、可审计、不依赖公网 SaaS 才能运行。

## 2. 用户与角色

| 角色 | 职责 | 典型操作 |
| --- | --- | --- |
| 平台管理员 | 部署、组织、模型、凭据、系统设置 | 配置 SSO、接入模型、管理密钥、查看健康状态 |
| Agent 构建者 / 实施工程师 | 交付客户 Agent | 安装能力包、编写指令、配置工具与技能、调试、发布 |
| 运营 / 审批人 | 处理运行中的审批与异常 | 审批高危工具、取消运行、查看用量 |
| 业务用户 | 使用 Agent（常通过业务系统或体验页） | 发起对话、上传文件、查看结果 |
| 外部开发者 | 将 Agent 接入业务系统 | 创建应用、申请密钥、调用 API、接收 Webhook |
| 审计 / 安全 | 检查合规 | 查询审计日志、权限矩阵、导出记录 |
| 运维 | 保障运行 | 部署升级、备份恢复、监控告警、排障 |

首版部署模型：**一套部署服务一个客户**；客户内再分组织单元、角色、用户。SaaS 多租户共享部署不在首版范围。

## 3. 范围与核心概念

### 3.1 配置层级

```
系统环境变量（基础设施）
  └─ 系统设置（数据库内，可热更新）
      └─ 安装实例配置（全局 / 组织 / 角色作用域）
          └─ Agent 版本（模型、指令、技能、工具、限制）
              └─ Run 策略快照（启动时冻结，运行期不可变）
```

### 3.2 资源关系

- **Agent** 有多个不可变版本；运行固定到某个版本。
- **Agent Pack** 可携带 Agent 定义、Prompt、Skill、MCP 配置、工具声明与依赖。
- **Skill / MCP / Tool / Model Provider** 都可独立安装，也可被包引用。
- **Installation** 表示某包版本在某作用域的安装实例；启用/停用作用于安装实例。
- **API App** 是开放平台调用主体，持有密钥、Scope、配额与 Webhook，可调用已发布且开放 API 的 Agent。

### 3.3 阶段标记

- `P0`：首个可交付版本，必须完成。
- `P1`：平台化增强，首个客户上线后迭代。
- `P2`：生态与规模化，按需投入。

### 3.4 配套专项文档

- 统一登录与 Agent Connector：[sso-and-connector.md](../02-architecture/sso-and-connector.md)
- 功能权限与数据权限：[permissions.md](../02-architecture/permissions.md)
- 线上发布流程：[release-process.md](../06-operations/release-process.md)

## 4. V1 现状与 V2 差距

V1 已确定：TypeScript + Pi 1.3.x、Temporal、Fastify + SSE、MySQL + Redis + 对象存储、私有化、治理与审批、错误码规范。V2 需要补齐：

| 差距 | V2 处理 |
| --- | --- |
| 只有内部 `POST /runs`，没有对外开放平台 | 新增 API App / Key / Scope / 配额 / Webhook / 开发者文档，见 `FR-OP` |
| 没有插件包格式与安装生命周期 | 新增统一包格式、安装工作流、作用域、热插拔语义，见 `FR-PL` |
| Agent / Skill / MCP 只能代码内配置 | 控制台可安装、新增、修改、启停、升级、回滚 |
| 模型依赖内置枚举，不能自定义 | Provider / Model / Route 三层配置，自定义 OpenAI-compatible 端点，见 `FR-MD` |
| 没有管理控制台 | 新增 Console 信息架构与页面，见 `FR-UI` |
| 只有一份设计文档 | 新增需求、接口、数据、目录、部署文档与 `AGENTS.md`，见 `FR-DLV` |
| MySQL 只列了表名 | 补齐表字典、DDL、索引、分区、保留、迁移、备份，见数据文档 |
| 缺少知识库、定时任务、评测、通知、用量等 | 定时任务提升为 P0；知识库/评测/通知按 P1/P2 补充 |
| 没有统一登录与公司调度系统接入 | 新增 SSO + Agent Connector 设计，所有公司项目强制接入，见 `FR-GV-22~26` 与专项文档 |
| 没有功能权限/数据权限管理体系 | 功能权限矩阵、数据范围、行级过滤、服务账号与授权预览，见 `FR-GV-13~21` |
| 没有发布标准 | 发布流程对齐公司 K8s/CI/Nginx 文档，新增 SSO/Connector/迁移闸门，见 `FR-DLV-07~08` |

## 5. 功能需求

### 5.1 Agent 构建与运行（FR-AG）

| ID | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-AG-01 | 创建、复制、编辑 Agent 草稿 | P0 | 必填名称/Key/指令/模型；Key 全局唯一；表单校验前后端一致 |

| FR-AG-04 | 组合配置模型、指令、Skill、工具集、MCP、限制、输出 Schema | P0 | 保存时校验引用存在且版本兼容；发布时做完整校验 |
| FR-AG-05 | 控制台调试运行 | P0 | 可选择草稿版本试运行；展示消息、工具调用、Token、成本、错误码 |
| FR-AG-06 | Agent 导入/导出为能力包 | P0 | 导出含引用依赖清单；导入可预检缺失依赖 |
| FR-AG-07 | 启用、停用、按组织/角色可见 | P0 | 停用后新 Run 被拒绝；运行中的 Run 按策略继续或取消 |
| FR-AG-08 | 多轮会话（Thread） | P0 | 同一 Thread 消息连续；可列出、重命名、删除 |
| FR-AG-09 | 运行中插话 | P1 | 消息在下一次模型调用前合入；SSE 可见；有幂等保护 |
| FR-AG-10 | 结构化输出校验与修复重试 | P0 | JSON Schema 校验；失败反馈模型至多 N 次；最终失败有 `OUT` 错误码 |

| FR-AG-13 | 灰度发布 | P1 | 按组织/角色/百分比分流；可一键回滚 |
| FR-AG-14 | 体验页 / 可嵌入聊天组件 | P2 | 可独立访问或嵌入客户系统；复用开放平台鉴权与配额 |

## 7. 关键用户旅程（验收场景）

1. **交付一个合同审查 Agent**：管理员配置自定义模型 → 构建者安装合同审查包 → 绑定 ERP OpenAPI 与文档解析 MCP → 试运行 → 发布并开启 API → 外部系统用 API Key 调用 → 高危提交审批 → 审批人通过 → 收到 Webhook。
2. **替换模型供应商**：管理员新增 OpenAI-compatible Provider → 测试连接 → 添加模型与价格 → 修改路由 → 新 Run 使用新模型；旧 Run 不受影响。
3. **下线一个 MCP**：查看引用方 → 迁移 Agent → 停用安装 → 排空运行中调用 → 卸载 → 审计可查。
4. **权限收敛**：销售组织只能看到销售 Agent 与 CRM 工具；越权调用被拒绝并记录。
5. **预算控制**：单 Run 超成本上限，状态变为 `budget_exhausted`，保留已有输出并推送事件。
6. **故障恢复**：worker 在执行工具后崩溃，重启后从下一步继续，外部写接口不重复执行。
7. **统一登录与权限**：用户通过 SSO 登录，Agent 角色映射为销售角色；只能看到本部门及子部门的 Run，消息正文对审计角色不可见；越权访问返回 404。
8. **定时任务**：运营创建每周一 9 点运行的 Agent 任务，以服务账号身份执行；并发策略 skip；失败告警；历史可查。
9. **合规发布**：新版本按公司 K8s/CI/Nginx 流程发布；数据库先迁移后滚动；SSO/Connector 开关默认关闭，验收后灰度开启；异常时 5 分钟内回滚镜像。

## 9. 假设、约束与不做

**假设**
- 客户内网可访问公网模型 API，或提供内网 OpenAI-compatible 端点。
- 三方业务系统提供 HTTP/OpenAPI；仅有 Python SDK 的通过 MCP 包装。
- 单客户数据量：Run 百万级/年以内；文件以文档为主。
- 公司项目可访问 Agent 平台/IdP 与 Agent Gateway；管理员能提供 System ID、Connector 凭据、OIDC 配置与 grant。
- 线上发布使用公司现有 K8s/CI/Nginx/镜像仓库/共享存储 基础设施。

**约束**
- 系统数据库只能是 MySQL 8.0.30+；测试也必须使用真实 MySQL。
- 生产登录必须走 SSO；本地账号只作应急管理员。
- 数据权限默认拒绝；行级过滤必须由 Repository 统一执行，不能靠前端或内存过滤。
- 发布必须遵循线上发布规范与本文发布闸门；数据库迁移人工审批、先备份后执行。
- 控制台是管理端，不是面向最终消费者的完整业务前端；体验页为 P2。
- Pi 版本锁定 1.3.x；升级只影响适配层。

**首版不做**
- SaaS 共享多租户、计费出账、移动端 App。
- 任意用户上传并执行代码；代码型扩展仅限运维安装的受信包。
- 可视化拖拽编排（Workflow Builder）；Agent 循环由框架固定。
- 自研文档解析/OCR 模型；通过 MCP 服务接入。
- 字段级脱敏、单条资源共享、ABAC 属性策略（P1/P2）。
